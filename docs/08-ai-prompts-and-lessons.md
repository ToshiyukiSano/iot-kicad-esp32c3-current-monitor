# 08 — Claude Codeへの指示例と、実際に起きた問題

AIに「回路を作って」とだけ伝えると、ピン配置やセンサーの仕様を推測で補われることがあります。**要件、一次資料、出力物、禁止事項、検証方法**を1回の指示に含めると、レビューしやすくなります。

## ① 接続確認

```text
KiCad MCPのget_project_infoを実際に呼び出して、KiCadのバージョン、CLIの場所、ライブラリ、working_dir、output_dirを表示してください。MCPツールを呼べなかった場合は、実行したふりをせず原因を説明してください。
```

## ② 回路図の生成

```text
KiCad 10のプロジェクトに、XIAO ESP32C3（A1/GPIO3）とSR-3704-150N（3000:1、80A、50/60Hz）を使う交流電流モニタの回路図を作成してください。CT負担抵抗は10Ω、バイアス約1.65V、フィルタ・入力保護を検討します。

仕様・ピン配列は公式資料と照合してください。未確定項目を明記し、KiCad MCPで .kicad_sch を生成、ERC・ネットリスト検査、PDFを出力してください。現段階でPCBやGerberは作らないでください。測定対象の商用電源を直接マイコンに接続する案は禁止します。
```

## ③ ピンとフットプリントのレビュー

```text
Seeed公式XIAO ESP32C3のピン配置と、シンボル1～14・PCBフットプリントのパッド番号を照合してください。ADC_A1=GPIO3、3V3、GND、5V未接続を確認してください。フットプリントは2.54mmピッチ、列間15.24mmの14ピン一体型を検討し、ERCとネットリストを再確認してください。
```

## ④ PCB配置・配線

```text
現行の回路図をバックアップしてKiCad 10のPCBを50×40mmの2層で設計してください。CT端子台J1とR1を近接配置し、ADC配線を短く、GNDの帰路を確保してください。ソケット・USB・U.FL・取付穴の干渉を確認し、DRCとschematic parityを報告してください。安全上の未解決事項を勝手に「問題なし」とせず、Gerber生成と製造発注はしないでください。
```

## ⑤ Firmwareと試験

```text
XIAO ESP32C3のA1(GPIO3)で交流電流を取得し、目標2kHz、200msごとにオフセットを差し引いてRMSを計算するArduinoスケッチを作成してください。Core版を明示してコンパイルし、サンプリング間隔とDMA欠損を実機で検証できるログを備えてください。未コンパイルなら明記。低電圧模擬負荷のみで試験し、CT二次側開放試験とGPIO規格外電圧の試験は禁止します。
```

## 起きた問題と対処

| 問題 | 発見方法 | 対処・教訓 |
|---|---|---|
| MCPがClaudeから見えない | `get_project_info`を呼べない | `claude mcp add --scope user ...`、セッション再起動 |
| XIAO右列のピン順が間違い | 公式ピンマップとの照合 | ERCだけに頼らない。14ピン一体型シンボルへ修正 |
| MCPコンパイルでフットプリントが消える | `.kicad_sch`/ネットリスト比較 | Footprint属性を再割当。スクリプト化して再実行 |
| MCPでPCB生成ができない | 実際のMCP機能を確認 | KiCad GUIのF8、pcbnew Python APIを使用 |
| シルクが外形や部品に重なる | DRCと3Dビュー | 文字・部品位置を調整、警告を安易に除外しない |
| ソケット2列の座標ずれの懸念 | フットプリント比較 | 14パッド一体型に統合 |
| 3Dモデルが見つからない | 公開資料/取得可否確認 | 公式基板データと標準部品で**近似モデル**、実寸検証が別途必要 |
| Arduino CoreのDLに失敗 | ツールチェーン導入ログ | リトライ・版固定。コンパイル成功とは言わない |

### 大切なルール

AIに生成させた設計・コードは、**人が確認して初めて次工程に進む**。不確かな点が残っているときは未解決としてGitHub Issue等に記録する。画像・シミュレーション・DRCの結果だけを「実機で成功」と表現しない。
